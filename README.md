# onelia

## Задание на проект

> Создайте на Go HTTP-сервис поиска маршрутов между городами.
> 
> Сгенерируйте тестовую транспортную сеть и сохраните её в выбранной базе данных. Для каждого участка укажите города отправления и прибытия, вид транспорта, время в пути и стоимость. Поиск должен использовать сохранённые данные.
> 
> По двум городам верните до трёх лучших маршрутов: последовательность участков, общее время и стоимость. Разрешены максимум две пересадки; повторное посещение города запрещено. Расписания и ожидание транспорта не учитываем.

## Поиск маршрутов

`GET /api/v1/routes` принимает query-параметры:

| Параметр    | Обязательный | Описание |
| ----------- | ------------ | -------- |
| `from_city` | да           | Название города отправления, например `Moscow` |
| `to_city`   | да           | Название города прибытия, например `Saint Petersburg` |
| `sort`      | нет          | `time` (по умолчанию) или `price` |

Названия должны совпадать с названиями в базе данных, включая регистр.
Пробелы по краям параметров удаляются. Названия с пробелами нужно URL-кодировать:

```bash
curl --get 'http://localhost:5050/api/v1/routes' \
  --data-urlencode 'from_city=Moscow' \
  --data-urlencode 'to_city=Saint Petersburg' \
  --data-urlencode 'sort=time'
```

Ответ — JSON-массив до трёх маршрутов. Каждый маршрут содержит `parts`,
`total_duration_minutes` и `total_price`; участки содержат города `from_city`
и `to_city` с полями `id` и `name`, вид транспорта, время и стоимость.
Время указано в минутах, стоимость — в копейках.
Маршруты включают максимум три участка (две пересадки) без повторного посещения городов.
При сортировке по времени одинаковые по длительности маршруты упорядочиваются по цене;
при сортировке по цене одинаковые по стоимости маршруты упорядочиваются по времени.

Пустые параметры, одинаковые города и неподдерживаемая сортировка возвращают HTTP 400.
Неизвестный город возвращает HTTP 404. Если между известными городами нет подходящих
маршрутов, возвращается HTTP 200 с пустым массивом `[]`.
